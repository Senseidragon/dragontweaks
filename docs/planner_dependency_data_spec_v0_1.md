## IMPLEMENTATION SUMMARY

### Storage

- File: `src/main/resources/data/dragontweaks/planner_dependencies.json`
- Loaded once at mod startup into a `PlannerDependencyRegistry` singleton
- At load time: graph is resolved into pre-computed chains per building and cached
- Cache is static for the session — JSON does not hot-reload

### Graph Structure

Each building entry is a node. Dependencies reference other node IDs. The engine resolves the full chain at load time by walking the graph depth-first, longest path first.

### Node Schema

```json
{
  "id": "fletcher",
  "display_name": "Fletcher's Hut",
  "aliases": ["fletcher", "fletcher's hut", "fletchery"],
  "research_required": "minecolonies:technology/stringwork",
  "university_level_required": 2,
  "depends_on": ["sawmill"],
  "building_prereqs": [],
  "notes": ""
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Unique key. Lowercase, no spaces. Used for graph resolution and goal input matching. |
| `display_name` | string | Human-readable name shown in panel |
| `aliases` | string[] | All strings the goal input will match against (case-insensitive exact match) |
| `research_required` | string (nullable) | ResourceLocation of required research. Null if no research gate. |
| `university_level_required` | int | Minimum University level to begin required research. 0 if no research gate. |
| `depends_on` | string[] | IDs of buildings that must exist before this one can be built. Empty if no building dependencies. |
| `building_prereqs` | object[] | Buildings that must reach a minimum total level before required research unlocks. See schema below. |
| `notes` | string | Optional authoring note — not shown in panel |

### Building Prereq Schema

```json
{
  "building_id": "forester",
  "min_total_level": 3
}
```

| Field | Type | Notes |
|---|---|---|
| `building_id` | string | ID of required building |
| `min_total_level` | int | Total level across all instances of that building type |

### Chain Resolution Rules

- Engine walks `depends_on` graph depth-first
- Longest dependency path surfaces first (blocking dependency first rule)
- Research steps inserted into chain at correct position: after building prereqs, before target
- Steps already satisfied (building exists at required level, research complete) are marked complete
- Material costs are NOT stored in JSON — looked up from MineColonies API at runtime per step

### Goal Input Matching

- Input normalized: lowercase, trimmed
- Matched against `id` and all `aliases` entries (exact match only)
- On no match: "did you mean" suggestions generated by finding all entries where input is a substring of `id` or any alias
- On no substring match: show full known building list

## DESIGN RECORD

### Graph + Cache Rationale

Graph structure chosen over flat list because buildings share dependencies — Sawmill and Blacksmith both depend on University, and expressing that once in a graph is more maintainable than duplicating it in every flat chain. Pre-resolved cache at load time means zero runtime graph-walking cost per player query.

### Material Costs at Runtime Rationale

Material costs not stored in JSON — looked up from MineColonies API at runtime. MineColonies recipe data can change with updates; storing costs in JSON creates a maintenance burden and a desync risk. Runtime lookup is always current.

### Alias Matching Rationale

Exact match against alias list rather than fuzzy. Aliases cover the common variants (plural, possessive, abbreviation). "Did you mean" substring fallback handles typos without fuzzy complexity.

### Seed Data Authoring Notes

- Only chains verified against lessons learned doc or wiki are marked complete
- Hospital and Mystical Site are included as stubs — research gate unverified, must be confirmed before these entries are treated as authoritative
- Remaining ~30+ buildings should be added incrementally as chains are verified
- Adding a building requires only a new JSON entry — no code change
